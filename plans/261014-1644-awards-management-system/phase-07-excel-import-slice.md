## Key Insights
- Same pure validator in `src/shared/import/` runs in browser (preview) and Worker (authoritative) -> identical messages, DRY.
- Template generated client-side from live data (Danh mục needs current units/teams/officers) instead of shipping static xlsx; column headers identical to `docs/import-template.xlsx`.
- Spec API has no batch id / preview endpoint -> extend `POST /api/awards/import` body: `{file_name, total_rows, batch_id?, dry_run?, include_duplicates, rows[<=30]}`. First commit call (no batch_id) creates `import_batches` row; later calls update counters.
- Query budget per request (free cap 50): session 1-2, master lookups 5 (batched), officers by codes 1, dup lookup 1 (`year IN`, `award_type_id IN`, `officer_id IN` / `unit_id IN`; <100 params), inserts 5 (6 rows x 15 cols = 90 params per stmt), batch create/update 1, audit 1 => ~16.
- Excel date cells: `cellDates:true`; dates converted to ISO client-side; strings accept dd/mm/yyyy or yyyy-mm-dd (shared `date-format`).
- Intra-file duplicates: client marks "Trùng với dòng … trong file" across whole file; server rechecks within its 30-row batch + against DB (earlier batches already inserted -> caught as DB dups).

## Requirements
- File: .xlsx/.xls/.csv, <= 5 MB, <= 100 non-empty data rows (limit changed 1000 -> 100 on 2026-10-14); first sheet only; missing required columns -> reject file listing missing column names.
- Row checks + exact messages from spec §5 table; Mã cán bộ kept as text; unit match by normalized name or code; team must belong to unit; officer must belong to unit/team given; Huân chương must be given as variant name; empty Cấp quyết định -> default authority.
- Preview table: row number, status (Hợp lệ / Lỗi / Có thể trùng), subject name, subject, award, year, decision no, errors; error rows red, dup rows yellow; checkbox "Nhập cả N dòng có thể trùng"; button "Nhập N dòng hợp lệ" shows exact count; "Chọn file khác".
- Commit: sequential batches of 30; progress indicator; on partial failure stop, show which rows saved (batch id) — re-upload is safe because saved rows now flag as duplicates.
- Success: toast "Đã nhập N khen thưởng", navigate `/`, invalidate awards queries.
- Endpoint `POST /api/awards/import` role ADMIN, EDITOR; returns `{batch_id?, results:[{row, status:'ok'|'error'|'duplicate'|'saved', errors[], duplicate_of?}]}`; dup rows saved only if `include_duplicates`.
- Audit: one IMPORT row per commit request (entity 'import_batch', detail {saved_ids_count, rows}).

## Architecture
```
file -> excel-file-reader (lazy xlsx) -> rows[][] -> header map -> import-row-validator(master, officerOptions)
     -> intra-file dup marking -> dry_run batches (30) -> server: revalidate + DB dup -> merge preview
user confirms -> commit batches (30, include_duplicates flag) -> server: revalidate, dup check, db.batch(inserts+batch row+audit)
```

## Risk Assessment
| Risk | L x I | Mitigation |
|---|---|---|
| CPU per 30-row request on free plan | Med x Med | measure on staging; reduce batch size constant (single place) if needed |
| SheetJS tarball unavailable at install | Low x Med | lockfile + commit tarball integrity; vendor tgz fallback in `vendor/` |
| Partial import across batches | Med x Low | batch row tracks counts; re-upload flags already-saved rows as dups |
| CSV encoding garbled | Med x Low | decode UTF-8; warn if replacement chars detected |

## Rollback
- Revert Worker version. Bad import: `UPDATE awards SET deleted_at=datetime('now') WHERE import_batch_id=?` (documented in runbook).

## Security Considerations
- Server never trusts client validation; row count + payload size caps (body <= 256 KB); formulas not evaluated (values only); xlsx parsed only in browser.
